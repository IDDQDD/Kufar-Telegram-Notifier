# Проверка прокси для Kufar — 11 октября 2026 года

Добавлены три адреса SOCKS5h из Нидерландов по геобазе [ProxyScrape](https://github.com/ProxyScrape/free-proxy-list): `79.137.198.71:7777`, `5.255.103.55:1080`, `45.114.60.178:1080`. Геобаза указывает расположение IP, но не устанавливает личность владельца прокси. Всего в `kufar-proxies.txt` шесть адресов; прежние три сохранены.

Проверки выполнялись с этого компьютера, не с VPS. Каждый адрес проверялся отдельно, без переключения на другой прокси и без прямого обхода. Использованы оба HTTPS API из кода бота, открытый поиск `samsung`, размер страницы 3 и User-Agent `Kufar-Telegram-Notifier/2.9.7`. Токены, пароли, личные поиски и файлы состояния не отправлялись. Для кандидатов действовали тайм-ауты бота для резервов: подключение 5 секунд, весь запрос 12 секунд. Недоступный прежний адрес также проверен с увеличенными тайм-аутами 10/20 секунд.

## Проверка HTTPS и границы безопасности

У всех пяти доступных прокси в последнем успешном ответе резервного API получен один и тот же сертификат:

- Subject: `CN=*.kufar.by`.
- Issuer: `GlobalSign GCC R6 AlphaSSL CA 2025`.
- SHA-256: `2D52EE690C3689ECF6C3F731F8620E11AFCA39126183C0DC0273A0D1CC3A8B31`.
- Проверка имени сервера и цепочки доверия прошла; curl завершился с кодом 0. Проверка сертификатов не отключалась, доверенные корни не изменялись.

Дополнительно через каждый из пяти доступных адресов выполнен запрос к `self-signed.badssl.com`: клиент отклонил самоподписанный сертификат с ошибкой недоверенного корня (curl 60). Через `85.209.156.148`, `5.255.99.75`, `79.137.198.71` и `5.255.103.55` запрос к `expired.badssl.com` был отклонён с `SEC_E_CERT_EXPIRED`. Через `45.114.60.178` этот тест завершился отказом SOCKS5 до TLS, поэтому по нему нельзя сделать вывод о проверке просроченного сертификата. У недоступного `213.176.74.119` все проверки завершились тайм-аутом; его TLS-поведение оценить не удалось. Значение `ssl_verify_result=0` при неуспешном соединении само по себе не считается успешной проверкой.

Признаков подмены сертификата Kufar в успешных проверках не обнаружено. Это ограниченная проверка текущих соединений, а не гарантия добросовестности владельцев, отсутствия журналов, анонимности или будущей безопасности. Проверки выполнялись Windows curl 8.21.0 / Schannel с доверенным хранилищем Windows; контейнер на VPS использует своё хранилище CA.

HTTPS при корректной проверке сертификата защищает содержимое запросов и ответов от чтения и изменения посредником. Даже `http://` прокси здесь используется как туннель к HTTPS API. HTTP и SOCKS5 сами по себе не шифруют связь с прокси. Оператор видит исходный IP клиента, домен назначения, время и объём трафика, может журналировать соединения и прекращать их. Для SOCKS5h имя назначения передаётся прокси для разрешения DNS. Если в доверенном хранилище установлен посторонний корневой сертификат, доверенная им подмена может пройти проверку; этот аудит не проверяет хранилище доверия пользователя на VPS. См. [правила проверки TLS в curl](https://curl.se/docs/sslcerts.html).

Публичные адреса нельзя считать проверенными и безопасными для всего личного трафика. Их использование здесь ограничено чтением открытого API Kufar с HTTPS; доверие к владельцам остаётся неизвестным.

## Маршрутизация бота и применение

В `src/networking.cpp` пул выбирается только для HTTPS URL с точным префиксом `https://api.kufar.by/` или `https://searchapi.kufar.by/`. Запросы Telegram, токен бота и загрузка резервных копий через этот пул не направляются. Это относится к пулу `KUFAR_PROXY`; сторонние системные настройки `HTTPS_PROXY`/`ALL_PROXY` являются отдельной настройкой окружения.

Проверены существующие тесты политики маршрутизации C++ и все 11 интеграционных тестов `tests/network_policy_tests.py`: успешно. Они проверяют оба API, отсутствие маршрутизации Telegram и похожих доменов через пул, сокрытие учётных данных в ошибках и переключение резервов. Интеграционные тесты повторно запущены вне ограниченной среды после отказов доступа к локальным соединениям и временному каталогу.

Адреса добавлены в исходники. Для применения на VPS перенесите обновлённые файлы и выполните обычное `bash update.sh`, затем проверьте `/app/Kufar-Telegram-Notifier --check-kufar` из контейнера, как описано в README. При заданном пользовательском `KUFAR_PROXY_POOL` встроенный файл не используется; такой пул потребуется обновить отдельно. Сервер в рамках этой задачи не обновлялся. Доступность публичных прокси меняется, а результаты с этого компьютера не гарантируют доступ с VPS.
