# Запуск на Arch Linux через Docker

Бот работает без открытых входящих портов. Нужен исходящий доступ к Telegram и Kufar.
Существующий Dockerfile собирает Linux-образ; Arch на сервере подходит, устанавливать C++ на сервер не нужно.

## 1. Подготовка

### Автоматически (рекомендуется)

Если Git ещё не установлен: `sudo pacman -Syu --needed git`. Затем:

```sh
git clone https://github.com/IDDQDD/Kufar-Telegram-Notifier.git
cd Kufar-Telegram-Notifier
bash deploy-arch.sh --prepare
```

Скрипт спросит разрешение на установку недостающих пакетов и включение Docker, создаст `.env` из шаблона и папку `data`. Существующие файлы не перезаписываются. Заполните `.env`; если есть резервная копия кеша, восстановите её по инструкции ниже, затем выполните:

```sh
bash deploy-arch.sh
```

Перед запуском скрипт проверяет конфигурацию и JSON кеша. Railway для запуска не нужен. Если кеша нет, потребуется отдельное подтверждение `NEW`, а для запуска — `START`. Никакие секреты скрипт не выводит и `.env` как команды не исполняет. При обновлении сначала `git pull --ff-only`, затем тот же скрипт. Запускайте его из обычного терминала, не через `curl | bash`.

### Вручную

Установите Docker и Compose (см. [ArchWiki](https://wiki.archlinux.org/title/Docker)):

```sh
sudo pacman -Syu --needed docker docker-compose docker-buildx git
sudo systemctl enable --now docker
git clone https://github.com/IDDQDD/Kufar-Telegram-Notifier.git
cd Kufar-Telegram-Notifier
cp .env.example .env
chmod 600 .env
mkdir -p data
chmod 700 data
```

Откройте `.env` любым текстовым редактором и заполните:

- `TELEGRAM_BOT_TOKEN` — действующий токен из BotFather. Не публикуйте его в GitHub и не присылайте в чат.
- `TELEGRAM_CHAT_ID` — ID основного получателя.
- `TELEGRAM_ADMIN_ID` — только ваш личный ID. В шаблоне указан `393943927`.
- `KUFAR_RECIPIENTS_JSON` — если есть сохранённая конфигурация, скопируйте значение **целиком**, с запросами обоих пользователей. Однострочный JSON заключите в одинарные кавычки. Если копии нет, эту переменную можно не задавать: пользователей и запросы добавите через меню.
- Если вместо списка получателей использовался `KUFAR_QUERIES_JSON`, перенесите его. Также перенесите `KUFAR_BEARER_TOKEN`, если он был задан.

Альтернатива длинному JSON в `.env`: добавьте массив получателей под ключом `recipients` в локальный `kufar-configuration.json`. Формат элементов: `{"chat-id":123,"queries":[...]}`. Значение `KUFAR_RECIPIENTS_JSON`, если задано, имеет приоритет. Личные запросы и токены не коммитьте.

## 2. Восстановление истории или новый запуск

**Не запускайте две копии с одним Telegram-токеном одновременно.** Они будут мешать друг другу получать команды; возможны повторные уведомления.

Если сохранилась резервная копия с прежнего сервера:

1. Перенесите сохранённые переменные в `.env` на Arch.
2. Поместите актуальный `cached-data.json` в `Kufar-Telegram-Notifier/data/cached-data.json` **до первого запуска**. Не используйте старую локальную копию без проверки её актуальности.
3. Запустите контейнер и проверьте `/menu`, `/queries`, `/status` у обоих пользователей.

Если Railway уже удалён и копии нет, восстановить историю объявлений из GitHub нельзя: кеш и секреты туда не сохранялись. Запускайте с новой историей, подключите товарища через «Пользователи» и добавьте запросы через меню. Первая проверка каждого нового запроса запоминает существующие объявления без рассылки. ID товарища из прежних настроек: `707549545`; ваш ID: `393943927`.

В кеше находятся история объявлений и минимальных цен, изменения запросов из меню, добавленные/отключённые пользователи и позиция обработки команд. Начальные запросы из переменных тоже нужны — один кеш не заменяет всю конфигурацию.

## 3. Запуск и обновление

```sh
sudo docker compose up -d --build
sudo docker compose ps
sudo docker compose logs --tail=100 -f
```

Выход из просмотра логов: Ctrl+C, бот продолжит работать. После перезагрузки сервера Docker запустит контейнер автоматически, если вы его ранее явно не остановили.

Обновление:

```sh
git pull --ff-only
sudo docker compose up -d --build
```

Остановка: `sudo docker compose stop`. Данные остаются в папке `data` на сервере, а не внутри временного контейнера. Не удаляйте эту папку при обновлении. Бот обрабатывает сигнал остановки и сохраняет состояние; Compose даёт ему до двух минут.

## Пользователи — только для владельца

В вашем `/menu` есть кнопка **👥 Пользователи** (также команда `/users`). У остальных её нет, и введённые вручную команды управления доступом им недоступны.

Подключение:

1. Друг открывает бота и нажимает Start или отправляет `/id`.
2. Передаёт вам показанный числовой ID.
3. Вы нажимаете «Добавить пользователя» и отправляете ID.
4. Друг отправляет `/menu` и добавляет собственные запросы.

При отключении бот просит подтверждение, удаляет только запросы и кеш выбранного пользователя. Отключение сохраняется после перезапуска, даже если его ID остался в начальной конфигурации. Повторное подключение через меню начинает его настройку заново. Самого владельца удалить нельзя. Работа с командами разрешена только в личной переписке, не в группах.

Имеющиеся пользователи и запросы при обновлении сохраняются. Новое меню ограничивает число активных пользователей до 100, а добавление запросов — до 200 поисков на человека (каждая выбранная категория считается отдельным поиском). Уже существующие запросы автоматически не обрезаются.

## Кеш и место на диске

По умолчанию:

| Настройка в `.env` | Значение | Что означает |
| --- | ---: | --- |
| `KUFAR_CACHE_RETENTION_DAYS` | 180 | Удалять объявления, не встречавшиеся в подходящей выдаче 180 дней |
| `KUFAR_CACHE_MAX_PER_USER` | 20000 | Максимум сохранённых объявлений на человека |
| `KUFAR_CACHE_MAX_TOTAL` | 100000 | Максимум записей суммарно по всем пользователям |

Очистка выполняется при сохранении состояния, в том числе при старте и после циклов проверки. При превышении лимита первыми уходят давно встречавшиеся записи. Вместе с ID удаляются цены и даты; неиспользуемые отметки старых запросов тоже убираются. При обновлении старые записи без даты получают полный срок хранения, а не удаляются сразу; ограничения количества применяются сразу.

Важно: после удаления записи из кеша её защита от повторов и история минимальной цены теряются. Если такое очень старое объявление снова появится в выдаче, бот может прислать его повторно. Бесконечную историю без роста хранилища эта схема не обещает. Увеличивайте лимиты при необходимости: дни — до 3650, каждый лимит количества — до 100000. Значения должны быть положительными.

Фотографии на диск не скачиваются. При заданных лимитах данные объявлений занимают обычно мегабайты, не гигабайты; это не жёсткая квота всего диска. На время атомарного сохранения нужен запас ещё на одну копию JSON. Лимит чтения кеша увеличен с 4 до 64 МиБ, чтобы выросший старый кеш можно было загрузить и очистить.

В Compose настроена [ротация Docker-логов](https://docs.docker.com/engine/logging/drivers/json-file/): три файла до 10 МБ. Это относится к новому контейнеру на Arch, не меняет настройки логов Railway.

Периодически проверяйте:

```sh
sudo du -sh data
sudo docker system df
df -h .
```

Docker-образы, кеш сборок и ваши резервные копии хранятся отдельно от кеша объявлений. Их бот не удаляет. Не запускайте бездумно общую очистку Docker volumes — там могут быть данные других сервисов.

Для резервной копии остановите контейнер, скопируйте `data/cached-data.json` в защищённое место и снова запустите `sudo docker compose up -d`. Храните ограниченное число копий. Секретный `.env` также нужен для восстановления, но должен храниться отдельно от публичного репозитория.
