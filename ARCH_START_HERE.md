# Всё для запуска Kufar-бота на Arch

Это единая памятка для переноса бота на свой Arch-сервер без Railway. Исходный код и
скрипт находятся в этом репозитории. Подробности и ручной способ запуска — в
[DEPLOY_ARCH.md](DEPLOY_ARCH.md).

## Что уже готово, а чего нет

- Dockerfile, `compose.yaml` и `deploy-arch.sh` готовы. Контейнер не требует открывать
  входящий порт и автоматически запускается после перезагрузки сервера.
- Проверка выполняется примерно каждые 5 минут (`KUFAR_LOOP_DELAY_SECONDS=300`).
  При большом количестве запросов один цикл может занять дольше пяти минут.
- Кеш хранится в `data/cached-data.json` на сервере, отдельно от контейнера.
  Старые записи ограничены сроком и количеством, а Docker-логи ротируются.
- На Arch-сервере бот **ещё не развёрнут**. Действующий токен в GitHub не хранится.
- Полная копия старого кеша и настроек, добавленных через меню, не получена. В GitHub
  нет ни полной истории объявлений, ни точного списка всех прежних поисков. Ниже
  записано только то, что можно восстановить из переписки и прежних журналов.

## Установка и запуск

В обычном терминале Arch-сервера:

```sh
sudo pacman -Syu --needed git
git clone https://github.com/IDDQDD/Kufar-Telegram-Notifier.git
cd Kufar-Telegram-Notifier
bash deploy-arch.sh --prepare
nano .env
```

В созданном `.env` задайте **действующий** токен от BotFather. Остальные нужные
значения уже есть в `.env.example`:

```dotenv
TELEGRAM_BOT_TOKEN=ВСТАВЬТЕ_ДЕЙСТВУЮЩИЙ_ТОКЕН_ТОЛЬКО_НА_СЕРВЕРЕ
TELEGRAM_CHAT_ID=393943927
TELEGRAM_ADMIN_ID=393943927
KUFAR_LOOP_DELAY_SECONDS=300
KUFAR_QUERY_DELAY_SECONDS=5
KUFAR_CACHE_RETENTION_DAYS=180
KUFAR_CACHE_MAX_PER_USER=20000
KUFAR_CACHE_MAX_TOTAL=100000
```

Не публикуйте `.env`, токен и кеш в GitHub и не пересылайте токен в чат.
Старый токен из прежней переписки не следует использовать. Если у вас есть
настоящая резервная копия `cached-data.json`, положите её в `data/` **до первого
запуска**. Если есть пара файлов, присланных ботом по `/backup`, восстановите
`kufar-configuration.json` в корне проекта и `cached-data.json` в `data/`;
старый `KUFAR_RECIPIENTS_JSON` в `.env` тогда не задавайте.

Для запуска:

```sh
bash deploy-arch.sh
sudo docker compose ps
sudo docker compose logs --tail=100 -f
```

При отсутствии кеша скрипт предупредит о новой истории и попросит ввести `NEW`,
а затем `START`. Выход из просмотра логов — `Ctrl+C`; бот продолжит работать.
Не запускайте одновременно две копии с одним Telegram-токеном.

Обновление: `git pull --ff-only`, затем `bash deploy-arch.sh`. Остановка:
`sudo docker compose stop`. Папку `data/` при обновлении не удаляйте.

## Пользователи и известные поиски

Владелец — `393943927`, товарищ — `707549545`. После запуска владелец отправляет
боту `/menu`, открывает «Пользователи» и добавляет ID товарища, если тот ещё не
восстановлен из конфигурации. Товарищ должен сначала открыть бота и отправить
`/start`. Каждый управляет своими поисками через «Мои поиски», «Новый поиск» и
«Удалить». `/status` показывает состояние, `/backup` доступна только владельцу.

Из переписки известны следующие пожелания владельца:

| Поиск или группа | Что важно сохранить |
| --- | --- |
| СССР; Часы Электроника; Осциллограф; трансформатор; микроскоп МБС-10 | Интерес к советской технике и старым вещам. |
| не включается; не проверял | Проверять именно сочетание слов и отрицание, а не отдельное «включается»/«проверял». |
| Блок питания | Проверять обе части фразы. |
| Неработающая советская и современная техника | Исключить телевизоры из этой группы запросов; точные формулировки старых поисков неизвестны. |

В прежних журналах дополнительно встречались действующие поисковые теги владельца:
`Юный радиолюбитель`, `Radiotechnika`, `S90F`, `Наковальня`. Это подтверждает
наличие таких поисков на момент последнего запуска, но не восстанавливает их
точные лимиты, категории и другие параметры.

Из переписки известны 11 запросов товарища:

1. `гиря`
2. `гиря 16кг`
3. `гиря 24 кг`
4. `гиря 32кг`
5. `гиря спортивная`
6. `Гараж`
7. `тиски СССР`
8. `тиски слесарные`
9. `Нож`
10. `ножи`
11. `Топор Fiskars`

Для всех вариантов «гири» подходит раздел «Спорттовары», а не все категории.
Поиск «Гараж» — **только в Минске**, в «Недвижимости → Гаражи и стоянки», только
от частных лиц, с исключением гаражных пролётов. Эти ограничения относятся
**только к гаражам**, не к остальным поискам. Категория гаражей подбирается
меню автоматически, но регион Минск и исключение пролётов через меню пока не
задаются. Чтобы сохранить именно эти условия, добавьте запрос в локальный
`kufar-configuration.json` до запуска. Ниже — **целый минимальный файл** с
гаражным поиском и пустым списком поисков владельца, чтобы остальные запросы
позже добавить через меню:

```json
{
  "telegram": {"bot-token": "", "chat-id": 393943927},
  "queries": [],
  "recipients": [
    {"chat-id": 393943927, "queries": []},
    {
      "chat-id": 707549545,
      "queries": [
        {
          "tag": "Гараж",
          "category": 1000,
          "sub-category": 1030,
          "region": 7,
          "seller-type": 0,
          "exclude-title-groups": [["гараж", "пролет"]]
        }
      ]
    }
  ],
  "delays": {"query": 5, "loop": 300}
}
```

Пустой токен здесь намеренный: бот получит настоящий токен из `.env`.
Проверка синтаксиса перед запуском выполняется скриптом. Если есть полноценная
резервная копия конфигурации, используйте её вместо этого частичного примера.
После добавления поисков через меню актуальный список сохранится в `data/`.

Объявления категории «Спрос» исключаются для обоих. Многословные запросы бот
перепроверяет по заголовку, а снижение цены сообщает при новом минимуме.
Повторяющиеся тексты запросов с разными категориями показываются одной строкой.

**Ограничение восстановления:** перед остановкой прежнего размещения было около
43 отдельных поисков (32 у владельца и 11 у товарища). В этой памятке нет
точной конфигурации оставшихся поисков владельца и старого кеша. Не считайте
перечень выше полной резервной копией. Без прежнего `cached-data.json` первая
проверка нового запроса запоминает существующие объявления без рассылки;
уведомления начнутся с последующих новых результатов.
