# Kufar Telegram Notifier

Бот на C++ для поиска новых объявлений Kufar и отправки уведомлений в Telegram. Запускается на Linux-сервере через Docker Compose. Владелец подключает пользователей, а каждый пользователь управляет своими поисками через меню бота.

## Как работает поиск

- Бот проверяет сохранённые запросы с выбранными категориями и фильтрами, получая выдачу от новых объявлений к старым.
- Первая успешная проверка нового поиска запоминает текущие объявления без рассылки. Со следующих проверок приходят новые объявления.
- История хранится отдельно для каждого пользователя. Уже доставленное объявление не отправляется ему повторно по пересекающимся поискам. При снижении цены ниже прежнего минимума приходит отдельное уведомление.
- Близкие русские словоформы, например «Книга», «Книги», «Книжка» и «Книжека», показываются одной группой в списке запросов. Каждый сохранённый вариант продолжает проверяться со своими фильтрами. Удаление группы удаляет все её варианты после подтверждения.
- По умолчанию новый цикл начинается каждые 300 секунд, между отдельными поисками есть пауза 5 секунд. Если полный обход занимает больше пяти минут, следующий цикл начнётся после его завершения.

Бот проверяет выдачу ваших запросов, а не все объявления сайта. Для каждого поиска запрашивается ограниченная страница — по умолчанию 30 объявлений. Если за интервал появилось больше объявлений, часть может оказаться за пределами этой страницы.

## Установка на VPS

Понадобятся Git, Docker Engine с Compose, токен от [@BotFather](https://t.me/BotFather) и ваш числовой Telegram ID. Для сборки желательно 2 ГиБ RAM и несколько ГиБ свободного диска. Серверу нужен исходящий доступ к Telegram и Kufar; входящие порты для бота не требуются.

Инструкции установки Docker: [Ubuntu](https://docs.docker.com/engine/install/ubuntu/) и [Debian](https://docs.docker.com/engine/install/debian/). Для Arch используйте [отдельную инструкцию](ARCH_START_HERE.md).

Скачайте репозиторий через Git:

```bash
git clone https://github.com/IDDQDD/Kufar-Telegram-Notifier.git ~/kufar-bot-git
cd ~/kufar-bot-git
bash deploy.sh --prepare
nano .env
```

`--prepare` создаёт `.env` и каталог `data`, сохраняя существующие файлы. В `.env` заполните:

```dotenv
TELEGRAM_BOT_TOKEN=YOUR_BOT_TOKEN
TELEGRAM_CHAT_ID=YOUR_NUMERIC_TELEGRAM_ID
TELEGRAM_ADMIN_ID=YOUR_NUMERIC_TELEGRAM_ID
```

Замените все заглушки своими значениями. Для владельца в обоих полях ID укажите один и тот же положительный числовой ID. Дополнительные настройки описаны в [.env.example](.env.example).

Запустите Docker и бота:

```bash
sudo systemctl enable --now docker
bash deploy.sh
sudo docker compose ps -a
```

Скрипт автоматически использует `sudo docker`, если текущему пользователю не хватает прав. Он собирает образ, запускает тесты, проверяет контейнер и доступ к поиску Kufar. При отказе поиска контейнер остаётся запущенным для Telegram и диагностики, а причина выводится в терминал.

В Telegram отправьте `/start`, `/menu` и `/status`, затем добавьте поиск через меню. Новый пользователь сначала пишет боту `/start` или `/id`, передаёт владельцу свой ID и получает доступ.

Для одного токена должна работать одна копия бота. Подробности переноса данных и подключения папки, установленной из ZIP, к Git — в [SERVER_SETUP.md](SERVER_SETUP.md). Команда `git pull` работает только в папке с репозиторием Git.

## Обновление

В папке установленного репозитория:

```bash
cd ~/kufar-bot-git
git pull --ff-only && bash update.sh
```

Обновление сохраняет `.env`, конфигурацию, пользователей, поиски и историю объявлений. Скрипт собирает новую версию и заменяет контейнер после успешных тестов. Останавливать службу Docker или вручную завершать процесс бота не требуется.

Для полной пересборки без кеша Docker:

```bash
git pull --ff-only &&
sudo docker compose build --no-cache --pull bot &&
sudo docker compose up -d --force-recreate --no-build bot
```

Параметры очистки запросов предназначены для отдельного удаления данных; при обычном обновлении они не нужны.

## Команды Telegram

| Команда | Действие |
| --- | --- |
| `/menu` | Открыть меню; отменить незавершённое действие |
| `/id` | Показать свой Telegram ID, в том числе до подключения |
| `/queries` | Показать свои группы запросов и варианты |
| `/add` | Добавить поиск через диалог: текст, категории и фильтры |
| `/delete` | Выбрать группу запросов для удаления с подтверждением |
| `/check` | Запросить проверку сейчас, сохранив историю |
| `/status` | Показать версию, результаты проверки, ошибки и размер состояния |
| `/users` | Владелец: показать пользователей с ID и именами |
| `/adduser 123456789 Иван Петров` | Владелец: подключить пользователя с необязательным именем |
| `/removeuser 123456789` | Владелец: отключить пользователя по ID после подтверждения |
| `/backup` | Владелец: получить конфигурацию и состояние для переноса |

Те же действия доступны кнопками меню. Управление пользователями и резервные копии доступны владельцу в личном чате.

Имя пользователя — до 80 символов в одну строку. `/adduser 123456789` работает без имени; повторная команда с ID подключённого пользователя и новым именем меняет подпись, сохраняя его поиски. Имена сохраняются после перезапуска и входят в резервную копию.

Удаление пользователя принимает **только числовой ID**. После подтверждения удаляются его имя, поиски и история; владельца отключить нельзя. Лимиты меню: 100 активных пользователей и 200 поисков по вариантам и категориям на человека.

## Подключение через прокси

Если Kufar отклоняет подключения с IP сервера, можно направить только его API-запросы через прокси с доступом к Kufar. Добавьте в `.env` адрес, проверенный именно с вашего VPS:

```dotenv
KUFAR_PROXY=socks4://PROXY_HOST:PORT
```

Поддерживаются `http://`, `https://`, `socks4://`, `socks4a://`, `socks5://` и `socks5h://`. Для прокси с авторизацией укажите учётные данные в адресе согласно его протоколу. Варианты `socks4a://` и `socks5h://` разрешают адрес назначения через прокси; `socks4://` и `socks5://` используют локальный DNS.

Примените настройку командой `bash update.sh`. Telegram через `KUFAR_PROXY` не направляется. Проверка сертификатов HTTPS остаётся включённой. Реальные адреса с паролями храните в `.env`, не публикуйте их в Git.

При заданном `KUFAR_PROXY` бот автоматически использует нидерландский пул из `kufar-proxies.txt`: `85.209.156.148:1080` (HTTP), `5.255.99.75:1080`, `213.176.74.119:1080`, `79.137.198.71:7777`, `5.255.103.55:1080` и `45.114.60.178:1080` (SOCKS5h). Основной адрес проверяется первым; дубликаты удаляются. Если соединение не удалось, тот же запрос повторяется через следующий адрес. Доступный прокси используется в следующих запросах. Каждый адрес API может проверить весь пул независимо от ошибок другого API. Для первой попытки действуют тайм-ауты 10/20 секунд, для резервных — 5/12 секунд. Прямого обхода пула нет. Эти публичные прокси возвращали объявления при проверке, но могут работать нестабильно. При повторной проверке 11 октября 2026 года `213.176.74.119:1080` не отвечал; остальные пять вернули объявления через резервный API.

Проверка безопасности и доступности всех шести адресов описана в [PROXY_AUDIT.md](PROXY_AUDIT.md). У пяти доступных адресов сертификат Kufar прошёл проверку, признаков подмены TLS в этих проверках не обнаружено. Владельцы публичных прокси неизвестны: они видят IP клиента, домен назначения, время и объём соединений и могут вести журнал. Содержимое запросов защищено HTTPS при доверенном хранилище сертификатов и включённой проверке TLS. Это не подтверждает безопасность прокси для всего личного трафика; пул применяется только к API Kufar, а Telegram и токен бота через него не отправляются.

Для замены прежнего основного прокси и всех пользовательских настроек пула выполните после обновления исходников `bash update.sh --netherlands-proxies`. Команда сохраняет копию `.env`, задаёт основной `http://85.209.156.148:1080`, удаляет старые `KUFAR_PROXY_POOL` и `KUFAR_PROXY_POOL_FILE` и запускает обновление. Остальные настройки и кеш не меняются. Обычный `bash update.sh` сохраняет существующие настройки прокси.

Чтобы заменить резервные адреса, задайте `KUFAR_PROXY_POOL='http://HOST:PORT;socks5h://HOST:PORT'` в `.env` либо `KUFAR_PROXY_POOL_FILE=/data/private-proxies.txt` с одним URL на строку. Явный пустой `KUFAR_PROXY_POOL` отключает встроенные резервные адреса. Пользовательский пул может содержать до 32 маршрутов и работать без основного `KUFAR_PROXY`.

Проверка доступа из запущенного контейнера:

```bash
sudo docker compose exec -T bot /app/Kufar-Telegram-Notifier --check-kufar
```

Команда проверяет основной и резервный адреса API, не вызывает Telegram и не изменяет состояние. Успешная проверка возвращает `OK, ads=...`. Ответ `HTTP 403` означает отказ API; изменение лимита кеша не устраняет такой отказ.

При настроенном прокси после **трёх подряд неудачных поисков из-за ошибок соединения, когда недоступны основной и все резервные прокси**, бот сообщает владельцу о проблеме. Одна попытка поиска включает весь пул и резервный адрес API, если он понадобился; отдельные ошибки прокси не увеличивают счётчик. Если хотя бы один прокси отвечает, уведомления о недоступности нет. Повторных сообщений о той же недоступности нет, в том числе после перезапуска. Успешное соединение сбрасывает счётчик; новая недоступность снова требует трёх ошибок. Если Telegram не принял уведомление, отправка повторяется при следующей ошибке поиска.

Поиск продолжает выполняться по расписанию. Ответы HTTP от Kufar, включая 403, и ошибки разбора объявлений не считаются недоступностью прокси и не вызывают переключение. Без настроенного основного прокси или пользовательского пула уведомления о прокси отключены.

## Данные и резервные копии

| Файл | Содержимое |
| --- | --- |
| `.env` | Токен, ID владельца, прокси и параметры запуска |
| `kufar-configuration.json` | Начальная конфигурация поисков и пользователей |
| `data/cached-data.json` | История объявлений, цены, изменения поисков и пользователей, отметки Telegram и состояние уведомления о прокси |

Рабочий кеш и `.env` исключены из Git. В исходной конфигурации нет личных поисков: добавляйте их через Telegram. Сохранённые изменения в состоянии перекрывают начальные списки при перезапуске. Переменная `KUFAR_RECIPIENTS_JSON`, если задана, переопределяет начальную конфигурацию пользователей из файла.

`/backup` отправляет два JSON-файла: конфигурацию и состояние. Токены в экспортированной конфигурации очищены; `.env` с секретами сохраните отдельно. Каждый отправляемый файл ограничен 45 МиБ. Большой кеш копируйте с сервера при остановленном боте. Для переноса восстановите конфигурацию и состояние до первого запуска, как описано в [SERVER_SETUP.md](SERVER_SETUP.md).

Ограничения по умолчанию:

| Ресурс | Лимит |
| --- | --- |
| Файл состояния | 500 МиБ при чтении и записи |
| История объявлений | 20 000 на пользователя; 100 000 суммарно |
| Хранение истории | 180 дней с последнего появления объявления в выдаче |
| Запас диска при записи временного файла | Не менее 64 МиБ |
| Память контейнера | 512 МиБ |
| Логи контейнера | 3 файла примерно по 10 МБ |

Размер файла и память контейнера — разные ограничения: большой JSON может потребовать больше 512 МиБ RAM. Во время сохранения на диске находятся основной файл и временная копия. Docker-образы, кеш сборки и резервные копии занимают дополнительное место. После удаления старой истории объявление может прийти повторно, если вновь появится в выдаче.

## Логи и диагностика

Все команды выполняйте в папке репозитория:

```bash
sudo docker compose ps -a
sudo docker compose logs --tail=150 bot
sudo docker compose logs --tail=100 -f bot
```

Строки `[SEARCH]`, `[SEARCH OK]` и `[FILTER]` показывают выполнение поисков и обработку объявлений. `/status` показывает последнюю завершённую проверку и причину ошибок. Сразу после добавления запроса отсутствие уведомлений ожидаемо: первая успешная выдача запоминается без отправки.

Остановить и снова запустить только этого бота:

```bash
sudo docker compose stop bot
sudo docker compose up -d bot
```

После остановки контейнера отдельно завершать его процесс не нужно. Если сообщения продолжают приходить или ответы дублируются, проверьте другие установки с тем же токеном. Защита общего файла состояния и повторных Telegram-событий не отключает независимую копию на другом сервере.

Порядок проверки мониторинга — в [SEARCH_AUDIT.md](SEARCH_AUDIT.md).

## Разработка

Сборка и тесты на Debian/Ubuntu:

```bash
sudo apt-get update
sudo apt-get install -y build-essential cmake libcurl4-openssl-dev python3
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
```

Тесты проверяют обработку API и фильтров, маршрутизацию прокси, меню, права доступа, сохранение состояния и повторные события. GitHub Actions также собирает Docker-образ, проверяет скрипты развёртывания и конфигурацию Compose.

Основные части проекта: `src/main.cpp` — меню и цикл мониторинга; `src/kufar.cpp` — API и объявления; `src/networking.cpp` — HTTP и прокси; `src/telegram.cpp` — Telegram; `include/useraccess.hpp` — доступ и имена; `include/usermenu.hpp` — список пользователей; `include/proxyhealth.hpp` — состояние уведомлений о прокси. Версия задана в `include/version.hpp` и `CMakeLists.txt`.
