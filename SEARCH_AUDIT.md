# Проверка мониторинга Kufar

Проверяйте доступ к Kufar из контейнера на том VPS, где работает бот. Успешный запрос с другого компьютера не подтверждает доступность с сервера.

## 1. Доступ к API

В папке репозитория выполните:

```bash
sudo docker compose exec -T bot /app/Kufar-Telegram-Notifier --check-kufar
```

Команда делает небольшой запрос к двум адресам:

- `https://api.kufar.by/search-api/v2/search/rendered-paginated`
- `https://searchapi.kufar.by/v1/search/rendered-paginated`

Она не вызывает Telegram, не запускает мониторинг и не изменяет настройки или историю. Корректный ответ содержит массив `ads`; пустой массив тоже допустим.

`HTTP 403` означает, что Kufar отклонил запрос до обработки объявлений ботом. Сначала проверьте доступ с IP сервера и, если используется прокси, через него. Удаление кеша не исправляет отказ API.

Ошибки соединения, таймауты и отказ прокси проверяйте с тем же адресом и протоколом, которые заданы в `.env`. Настройка `KUFAR_PROXY` действует только для API Kufar; Telegram подключается отдельно.

## 2. Выполнение поиска

Отправьте `/queries` и `/status`, затем запросите проверку через `/check`. Посмотрите логи:

```bash
sudo docker compose logs --tail=150 bot
```

Ожидаемое поведение:

- `[SEARCH]` показывает начало проверки сохранённого запроса.
- `[SEARCH OK]` и `[FILTER]` показывают результат API и обработку объявлений.
- Первая успешная проверка нового поиска запоминает существующую выдачу без уведомлений. Неудачный запрос не завершает такую инициализацию.
- Последующие проверки отправляют новые объявления; после подтверждения Telegram пересекающиеся поиски не отправляют одно объявление тому же пользователю повторно.
- Начальная выдача нового поиска хранится отдельно от подтверждённых доставок и не подавляет новые уведомления по уже активному поиску.
- Резервный адрес API получает те же поисковые параметры и фильтры. Если оба адреса недоступны, ошибка видна в `/status`.

Каждый поиск получает ограниченную страницу свежих объявлений. Бот не обходит все объявления Kufar. Если полный цикл длится больше заданного интервала, следующий цикл начинается после его завершения.

## 3. Уведомление о недоступности прокси

Если `KUFAR_PROXY` задан, три подряд неудачных поиска из-за ошибок соединения приводят к уведомлению владельца. Обращение к основному и резервному API в одном поиске считается одной попыткой.

Счётчик и отметка отправленного уведомления сохраняются в состоянии. Перезапуск не создаёт повторное сообщение о той же недоступности. Успешное соединение сбрасывает счётчик. Ответы HTTP, включая 403, и ошибки разбора ответа не считаются недоступностью прокси. Если Telegram не принял уведомление, бот повторяет отправку при следующей ошибке поиска. Без настройки прокси этих уведомлений нет.

## 4. Команды и данные

Владелец подключает пользователя командой `/adduser ID имя`; имя необязательно. Повторное добавление активного ID с новым именем меняет подпись. Удаление принимает только ID и требует подтверждения. Имена не предоставляют доступ и не используются вместо ID.

Повторно доставленное Telegram-событие и повтор того же сообщения пропускаются; новое нажатие кнопки обрабатывается. На Linux и macOS блокировка файла состояния запрещает вторую копию с тем же кешем. Она не защищает от независимых установок с отдельным кешем, поэтому для токена должен работать один экземпляр.

Обычное обновление сохраняет настройки, пользователей, поиски и историю. При ошибке записи состояния предыдущий файл остаётся на месте; проверьте логи и свободный диск перед восстановлением резервной копии.

## Автоматические проверки

Тесты проекта проверяют:

- Парсинг объявлений, даты, цены и фильтры; переход на резервный API.
- Маршрутизацию только API Kufar через прокси и сохранение прямого подключения Telegram.
- Новые объявления, начальную выдачу, пересекающиеся поиски и подтверждённую доставку.
- Права владельца, имена пользователей, удаление по ID и сохранение после перезапуска.
- Порог трёх ошибок, отсутствие повторных уведомлений, восстановление соединения и отказ отправки Telegram.
- Отключение уведомлений без прокси и исключение HTTP 403 из ошибок его доступности.
- Повторные команды, сохранение кеша, расписание и скрипты развёртывания.

GitHub Actions собирает Docker-образ с тестами и проверяет Compose. Эти проверки подтверждают поведение кода; доступность внешнего прокси и Kufar на вашем VPS проверяйте отдельной командой `--check-kufar`.
